# M1 分离度实验：结果与对方案的修正（2026-07-28）

预注册在 `bench/exp/m1_separation.py` 的文件头，写在第一次跑之前。快照
`bench/results/M1-20260728-111613.json`。240 个分离度 probe（4 臂 × 3 facet × 20）
+ 60 个 dilution probe，零 judge，全部机械子串判定。

## 判决：FAIL

```
死条目泄漏（注入时） = 0.85   门槛 >= 0.60   ok
real - recency-32 的 SUPPRESS 差 = +0.00   门槛 >= 0.15   MISS
```

两个门槛只过了一个，按预注册规则判 FAIL。**不要写那 480 条语料。**

## 四个臂的实测

| 臂 | 注入条数 | CARRY | SUPPRESS | 死条目泄漏(边际) | 越界泄漏(边际) | 死条目泄漏(注入时) | noop |
|---|---|---|---|---|---|---|---|
| real | 32.0 | 0.60 | **1.00** | 0.00 | 0.00 | n/a（0 次注入） | 0.10 |

## 三条结论，两条是坏消息

### 1. 生命周期能测，检索不能测

suite 分得开「有失效逻辑」和「没有」：real / recency-32 的 SUPPRESS 是 1.00，
null-dump 是 0.57，差 **0.43**。死条目一旦进了 prompt，有 **0.85** 的概率被带进改写——
陷阱是有效的，不是摆设。

suite 分不开「聪明的检索」和「取最新 32 条」：real 与 recency-32 的 SUPPRESS 差
**恰好 0.00**。两者都靠 `status` 过滤挡住死条目，而 `recall()` 多做的那两件事
（scope 过滤、key 排序）在这套判据上一分钱都没换到。

预注册门槛写的就是 real vs recency-32，所以判 FAIL。这不是门槛定错了——
它精确地问出了「480 条语料能不能买到区分度」，答案是买不到。

### 2. `_scope_ok` 的观测贡献是零，而且这次是直接测出来的

recency-32 不做 scope 过滤，所以越界规则 **60/60 全部进了 prompt**，
而它被带进改写 **0/60**。翻译器自己按话题判断就把越界规则挡掉了，
`_scope_ok` 没有产生任何可观测的行为差异。

这与 `translate._requirement_block` 只打印 `- [id] text`、scope 字段从不进 prompt
是同一件事的两端：产品既没有把 scope 告诉模型，也不需要——模型自己会过滤。
**scope 维度应当整个退出计分**，或者先改产品（scope 进 prompt）再谈测它。

### 3. CARRY 有稀释效应，之前那条"CARRY 不敏感"是小样本假象

| 注入条数 | CARRY |
|---|---|
| 5.7 | 0.70 |
| 27.7 | 0.63 |
| 32.0 | 0.50 |

n=60/格，单调下降 20 个点。对抗复核当时测的是 6/6、5/6、5/6（n=6），据此判定
"CARRY 对注入集合几乎不敏感"，并把 headline 权重从 0.6 压到 0.25。**这个依据不成立**，
权重决定要重做。

（注意 null-dump 的 CARRY=0.00 是构造产物不是发现：它取插入序的头 32 条，而 live 规则
按构造是最新的，所以它结构上不可能带上——这个臂只有死条目那一列有意义。）

## 顺带打掉方案里的一根承重柱：distinctive 码活不过改写

第一版 M1 用发明的编码当标记（`QX-4417`），CARRY 全线 0.00。实际输出：

```
注入：邮件结尾另起一行写备案号 QX-4417
改写：给供应商写封邮件催一下上个月的发票。邮件正文开头标注版本号，邮件结尾另起一行写备案号。
```

规则带过去了，编码被规范化掉了。合成方案把 gate 压在 `E-mech` band
（权重 0.50，卖点是"全部零 judge 在环、`not_contains(distinctive)`"）——
**这个 band 建在一个不成立的前提上**。

改法已落进实验代码并有效：不用编码，用**语义对立的前后继对**，对比词是规则内容的一部分
（座机↔手机号、版权声明↔作者、三级↔一级），改写时会被带过去。副作用是"推翻"必须改变
规则内容，这本来也更真实——只换个编码的 supersede 是假的。

## 该怎么改计划

1. **语料缩量，重心从广度移到失效。** 唯一实测有区分度的资源是失效事件与死条目 probe
   （0.43 的臂间差全部来自这里）。480 条铺 12 个 episode 的宽度买不到东西。
2. **scope 退出计分**，降为观测；或者先修产品（scope 进 prompt）再重跑本实验。
3. **CARRY 权重重议**，0.25 的依据（n=6）已被 n=60 推翻。
4. **`E-mech` band 重新定义**：distinctive 码不可用，机械判据只能建在语义对立对上，
   这限制了哪些 constraint 可以进 mech band——不是所有规则都有天然的对立面。
5. 重跑门槛：修产品之后，`real - recency-32` 的差应当来自 scope 过滤真正生效。
   在那之前，Suite E 能诚实声称的只有一句：**被撤回的规则会不会停止生效**。

## 复现

```bash
eval "$(grep '^export ANTHROPIC_API_KEY=' ~/.zshrc)"
uv run python -m bench.exp.m1_separation 20 --workers 4
```

`with_retry` 但仍建议 4。
